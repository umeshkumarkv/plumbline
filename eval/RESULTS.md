# Eval results — Broker-Dealer OMS (2026-10-13/14)

Codebase: `umeshkumarkv/broker-dealer` @ local export of `develop` (9 services, 313 main + 81 test Java files).
Everything below is measured. Raw data is in `eval/<run>/` (gate results, anonymised critic verdicts, answer keys, judge files).
Anonymised diffs are committed alongside each run and are regenerated byte-for-byte (seeded) by `harness.py gates`.
Gate snapshots: commit `ea36bbf` (first commit) = v2 **plus** the class-suffix fix; it reproduces set-1 v2 exactly and set-2 v2 except the two C2 false alarms (P03, P29). The authoritative v2 set-2 record is `set2-gates-v2-critic-judge/gates.json`. **v3 = current.** v1 was edited in place before the first commit and is not preserved; v1 numbers are as recorded in `set1-gates-v1-critic/gates.json`.

## Method

| Step | Who | Isolation |
|---|---|---|
| Write gates | Orchestrator | — |
| Set 1: 50 single-change defects + 15 benign controls | Defect-author agent A | Never saw the gate rules |
| Set 2: 30 PR-sized defects (40–107 changed lines) + 10 controls | Defect-author agent B | Never saw set 1, the gates or any result. **Caveat:** the orchestrator's prompt to B named example idioms for some defect types (integer cents ÷ 100.0, UTC market hours, `ROUND_DOWN`, a transition map allowing a backward move) |
| Review | 9 critic agents (5 on set 1, 4 on set 2) | Fresh context; saw only anonymised diffs, CLAUDE.md and the clean code; never saw defects, answer key or gate output |
| Score set 2 | Judge agent | Wrote neither defects nor reviews; a catch counts only if a finding hits the planted defect's location/mechanism |
| Bias probe | 4 critics on set 2 primed with the author's "complies with CLAUDE.md, tests pass" self-review | Otherwise identical |

### Set 2 with gates v3 (training — reported for completeness)
Planted defects caught: mechanical 5/10, judgement 1/10, domain 4/10. Of those, P01 (integer cents), P21, P22 and P24 match idioms named in the author prompt, and P28 matches a rule written after reading the set-2 descriptions, so treat 10/30 as an upper bound, not a measure. Control flags: 1 (Q10, a real missing-test violation).

### Domain gates — the fair number
Set 1's 11 domain defects were not read before the v3 domain rules were written, **except** that D50's idiom (cross-schema SQL) was also seen in set 2 before the boundary rule. Fair count: **1/11** (D45, rounding mode); 2/11 including D50. **Deterministic gates barely touch domain logic.** The critic caught all 21 domain defects across both sets with the rulebook alone. The domain rule pack makes those rules explicit for critics.

### Bonus findings on the real codebase
- **26 pre-existing violations** (one per rule per line) recorded as baseline debt on `develop`: 3 non-UUID primary keys; `java.util.Date` in `JwtService`; a `DROP TABLE` in `V12__fix_ticks_numeric_precision.sql`; 9 suffix/package deviations; 1 mutable response DTO; `MarketCloseScheduler` setting `EXPIRED` via `setStatus()` outside the state machine; trading-day logic in `OrderService` and `KycVerifiedRule` using UTC or the JVM default zone instead of America/New_York; 5 unbounded `findAll()` calls in request paths.
- **The critics surfaced 29 real issues nobody planted,** mostly missing or broken tests. Two "clean" controls (Q03, Q08) would break existing unit tests (by inspection; not compiled).

## What this shows

1. **Gates and critic do different jobs.** Gates are deterministic, free and repeatable, and they produce proof. They own the mechanical rules but generalise poorly to unseen idioms (4/10 held-out mechanical). The critic covers judgement and domain.
2. **A fresh-context critic with the rulebook is strong on this codebase:** 79/80 planted defects, very few false alarms.
3. **Priming with a persuasive PR description barely moved it.** The isolation claim is therefore supported by design and by this probe, **not** measured head-to-head against same-context self-review.

## Limits — read before quoting these numbers

- **Same model family everywhere** (defect authors, critics, judge). The defects may be the kind this model finds easy. Customer-authored and real escaped defects are required before any external claim.
- **Small samples:** 80 defects and 25 controls; per-kind cells of 10–23.
- **Not tested:** a critic sharing the generator's full transcript (true self-review).
- **Set 2 is partly contaminated for domain/money gates** (idioms named in the author prompt). Use set 2 only for the critic and for gates v2.
- **One judge pass** on set 2; set 1 critic recall scored without a location check.
- **No compilation:** Maven Central was blocked, so planted defects, ArchUnit and JUnit specs were not executed.
- **Cost not measured** in this environment.
